# ADR-004: BullMQ for Async Job Processing

**Status:** ACCEPTED

## Context
The platform needs async processing for email delivery, OTP expiry, session expiry, audit logging, and data archiving without blocking the request-response cycle.

## Decision
Use BullMQ (Redis-backed queue) for all async job processing, with separate queues for email, OTP, audit, and background jobs.

## Consequences
+ Persistent queue (Redis-backed) — survives worker restarts
+ Separate queues prevent head-of-line blocking
+ Built-in job scheduling (repeatable jobs for background tasks)
- Requires Redis — additional infrastructure dependency
- No Redis persistence configured (potential data loss)
- Workers start new Repository instances each tick (no DI singletons)

## Evidence
- `backend/src/modules/notification/email.queue.ts`: Email queue definition
- `backend/src/modules/worker/`: Worker implementations
- `backend/src/modules/email/`: Email worker and renderer
