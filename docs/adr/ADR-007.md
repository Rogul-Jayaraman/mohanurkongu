# ADR-007: Role-Based Authorization via JWT Claims

**Status:** ACCEPTED

## Context
The platform has multiple user types (USER, ADMIN, SUPER_ADMIN) requiring different access levels. A scalable authorization mechanism is needed.

## Decision
Embed roles as a claim in the JWT access token during login/signup. The `requireAuth` middleware decodes the JWT and attaches user info (including roles) to the request. A `requireRole` guard function is defined for route-level enforcement.

## Consequences
+ Stateless authorization — no DB lookup per request
+ Roles travel with the token, easy to verify in middleware
- `requireRole` guard is defined but NEVER used in any route (BUG-ADMIN-003)
- Role changes don't take effect until token refresh (15 min max)
- No route-level authorization currently enforced
- PORTAL field check in login is optional — can be bypassed (BUG-MED-004)

## Evidence
- `backend/src/common/guards/role.guard.ts`: requireRole function (UNUSED)
- `backend/src/common/middleware/requireAuth.ts`: JWT verification, sets req.user
- `backend/src/modules/auth/auth.service.ts`: login() portal check
