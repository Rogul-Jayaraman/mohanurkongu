# ADR-008: SHA-256 for OTP Hashing

**Status:** ACCEPTED

## Context
OTP codes need to be stored for verification but must not be stored in plaintext. The OTP is short-lived (5 minutes), so a fast hash is acceptable.

## Decision
Use SHA-256 (not Argon2id) to hash OTP codes before storage. The OTP is plaintext 5 digits, and the service returns it (controller discards it) — making Argon2id's work factors unnecessary.

## Consequences
+ Fast — no work factor overhead for short-lived tokens
+ SHA-256 is sufficient for data-at-rest protection of 5-digit OTPs
- SHA-256 is fast — allows brute-force attack. Mitigated by 5-attempt limit and 5-min TTL
- OTP returned as plaintext from service layer (controller doesn't propagate it, but BUG-CRIT-001 means the user never gets it)

## Evidence
- `backend/src/modules/auth/auth.service.ts`: `sha256(plainOtp)` for storage
- `backend/src/common/utils/hash.ts`: sha256 function
- Verification record has `attempts` (max 5) and `expiresAt` (5 min)
