# ADR-002: JWT Access Tokens + Rotating Refresh Token Sessions

**Status:** ACCEPTED

## Context
The platform needs stateless API authentication for microservice compatibility, combined with session revocation capability for security.

## Decision
Use short-lived JWT access tokens (15 min default) for API authentication, and long-lived refresh tokens stored as SHA-256 hashes in the `sessions` table. Refresh tokens rotate on each use (old token revoked, new token issued).

## Consequences
+ Stateless access tokens — no DB lookup on each request
+ Session revocation via DB (logout, logout-all, password change)
+ Refresh rotation provides token family detection
- Increased complexity (two-token system)
- Concurrent refresh race condition (BUG-HIGH-001)
- Cookie path `/auth` leaks to public endpoints (BUG-MED-001)

## Evidence
- `backend/src/common/utils/jwt.ts`: signAccessToken, signRefreshToken, verifyAccessToken, verifyRefreshToken
- `backend/src/modules/auth/auth.service.ts`: login, refresh, signup all create sessions
- `backend/src/modules/session/session.service.ts`: rotateSession, revoke, revokeAll
