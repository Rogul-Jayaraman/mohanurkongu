# ADR-014: Admin Approval Workflow for Profile Activation

**Status:** ACCEPTED
**Date:** 2026-05-25

## Context

Previously, `POST /profiles/publish` transitioned a profile directly from DRAFT to ACTIVE, making it immediately visible to other users. This bypassed any moderation or quality review. Conflicts C3 and C4 identified that:

- **C3 — Profile submitted directly to ACTIVE**: No moderation gate existed between submission and visibility.
- **C4 — No REJECTED status**: Profiles could only be ACTIVE, INACTIVE, or DELETED — no mechanism to return a profile to the user for correction.

## Decision

Profiles now submit to PENDING status. Admin approval is required to reach ACTIVE:

1. **`POST /profiles/create`** — validates and transitions to PENDING. Profile is not visible to other users.
2. **`POST /admin/profiles/:id/approve`** — admin-only action. Transitions PENDING → ACTIVE, sets `approvedAt`/`approvedBy`, generates regNo if not already set on create.
3. **`POST /admin/profiles/:id/reject`** — admin-only action. Transitions PENDING → REJECTED, sets `rejectedAt`/`rejectedBy`/`rejectionReasonEn`/`rejectionReasonTa`.

### REJECTED Status

- Profiles in REJECTED status include machine-readable rejection reasons (English + Tamil)
- `getProfile()` returns the rejection reason to the profile owner
- REJECTED profiles cannot be directly approved — they must be corrected and re-submitted

## Consequences

+ Quality gate before profiles become visible to other users
+ Clear feedback mechanism via rejection reasons (bilingual)
+ Audit trail for all approval/rejection actions
+ `ProfileStateHistory` records every status transition with `changedBy`

- Admin UI needed to list PENDING profiles and approve/reject
- Users see "Pending Approval" after submitting (may need communication)
- REJECTED → re-submit flow not yet implemented (requires new draft)

## Evidence

- `backend/prisma/schema.prisma`: `ProfileStatus` enum includes `REJECTED`; Profile model has approval/rejection columns
- `backend/src/modules/profile/profile.service.ts`: `approveProfile()`, `rejectProfile()` with transaction boundaries
- `backend/src/modules/profile/profile.controller.ts`: approve/reject handlers
- `backend/src/modules/profile/profile.routes.ts`: admin routes with `requireRole('ADMIN')`
- `backend/src/modules/profile/profile.repository.ts`: `findPendingById()`
- `backend/src/modules/profile/dto/reject-profile.dto.ts`: `reasonEn` required, `reasonTa` optional
- `backend/src/modules/profile/dto/approve-profile.dto.ts`: empty body (approval needs no additional data)
