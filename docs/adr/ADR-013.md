# ADR-013: Single Profile Create Path (No Separate Publish)

**Status:** ACCEPTED
**Date:** 2026-05-25

## Context

The original design had two distinct submission endpoints: `POST /profiles/draft` (save in-progress work) and `POST /profiles/publish` (make profile active and visible). This caused multiple issues:

1. **C1 — Draft and Create share validation**: The `saveDraftSchema` (which must accept partial data) was also used for publish validation, creating a conflict between "accept anything" and "require everything."
2. **C2 — publish endpoint uses saveDraftSchema**: The publish endpoint imported the same Zod schema as draft, missing required-field enforcement.
3. **C5 — profileData is mutable across both operations**: The same `profileData` object was used for both draft save and publish, creating cross-contamination risk.

## Decision

Remove `POST /profiles/publish`. Replace with a single `POST /profiles/create` endpoint that:

- Accepts optional `profileId` (omitted for fresh profiles, set to draft ID for draft→submit)
- Requires `firstName` for validation (with symbol/number check)
- Performs full business validation (required sections, cross-field rules)
- Submits to PENDING status (not ACTIVE — see ADR-014)
- Returns `{ profileId, status: "PENDING" }`

## Consequences

+ Single submission path eliminates double-endpoint confusion
+ Draft and Create have distinct validation schemas and behaviors
+ `createProfileSchema` can enforce firstName rules that `saveDraftSchema` should not
+ Cleaner frontend flow — one submit button, one API call
+ Frontend no longer needs to distinguish "is this a publish or a create"

- Existing API clients must migrate from `/profiles/publish` to `/profiles/create`
- `PublishLog` table becomes deprecated (kept for backward compatibility)

## Evidence

- `backend/src/modules/profile/profile.routes.ts`: publish route removed, create route added
- `backend/src/modules/profile/profile.service.ts`: `publish()` removed, `createProfile()` replaces it
- `backend/src/modules/profile/dto/publish.dto.ts`: deleted
- `backend/src/modules/profile/dto/create-profile.dto.ts`: created with firstName validation
- `frontend/src/api/profile.api.ts`: `publishProfile` removed, `createProfile` added
- `frontend/src/components/features/user/NewProfile.tsx`: single `handleSubmit` calling `createProfile`
