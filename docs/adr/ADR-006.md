# ADR-006: In-Memory Access Token Storage

**Status:** ACCEPTED (Refactored)

## Context
The frontend needs to store JWT access tokens between API calls. The original implementation used localStorage, which is vulnerable to XSS-based token theft.

## Decision
Store the access token in a JavaScript module variable (in-memory) rather than localStorage. On page refresh, use the httpOnly refresh token cookie to obtain a new access token.

## Consequences
+ XSS-resistant — access token not accessible from storage APIs
+ Automatic token refresh via Axios interceptor on 401 responses
+ Refresh token in httpOnly cookie is not accessible to JavaScript
- Access token lost on page refresh (mitigated by silent refresh via cookie)
- Refresh queue to prevent concurrent refresh storms

## Evidence
- `frontend/src/lib/session.ts`: `_accessToken` module variable
- `frontend/src/lib/api.ts`: Axios interceptor with 401 → silent refresh pattern
