# ADR-015: Backend Draft Validation Limited to Structural Checks

**Status:** ACCEPTED
**Date:** 2026-05-25

## Context

The original `saveDraft` endpoint performed business validation on draft saves — for example, it would throw an error if a user provided `casteId` without `communityId` in the community section (C7). This violated the principle that drafts should accept partial data. Additional conflicts:

- **C1 — Draft and Create share validation**: The same schema was used for both; draft could not accept partial data while also enforcing required fields.
- **C6 — Frontend validation skipped on submit**: Because backend enforced rules, frontend had no `validateProfileCreate()` function — it relied on the server to catch errors.
- **C7 — Community throw on incomplete**: `casteId` without `communityId` threw an error during draft save.
- **C8 — ProfileBasic not guarded**: Required DB columns (`profileForId`, `gender`, `dob`, `diet`, `heightId`) could be null on draft save only because Prisma nullable columns existed; but the service did not handle this gracefully.

## Decision

### For Backend Draft Validation
- **NO business completeness validation** during draft save
- Structural validation only: FK reference checks, upload ownership, Zod type validation
- If community data is incomplete (e.g., caste without community), silently skip the section update instead of throwing
- Required basic fields (`profileForId`, `gender`, `dob`, `diet`, `heightId`) that are null during draft save are preserved in IndexedDB — the next draft save retries

### For Frontend Create Validation
- A new `validateProfileCreate()` function performs full business validation before submission
- This includes: required sections check, firstName character validation (no symbols/numbers), age >= 18, agreedToTerms

### For Backend Create Validation
- The `createProfileSchema` re-validates all required fields independently
- This provides defense-in-depth — even if frontend validation is bypassed, the server enforces rules

## Consequences

+ Drafts can accept truly partial data without errors
+ Frontend carries the validation responsibility where it belongs (immediate feedback)
+ Backend create endpoint provides independent validation (defense-in-depth)
+ Community section: incomplete data silently skipped instead of throwing (data preserved in IndexedDB)

- Backend draft no longer catches data integrity issues early
- Users may save a draft that can never be submitted (if critical data is missing)
- Slightly more complex mental model: "draft validates nothing, create validates everything"

## Evidence

- `frontend/src/utils/validation.ts`: `validateProfileCreate()` with full business rules
- `frontend/src/components/features/user/NewProfile.tsx`: `handleSubmit` calls validation before API
- `backend/src/modules/profile/profile.service.ts` `upsertSections()`: removed business validation throw, silent skip for incomplete community
- `backend/src/modules/profile/dto/create-profile.dto.ts`: separate schema with firstName validation
