# ADR-011: Monorepo Structure with Shared Configs

**Status:** ACCEPTED

## Context
The platform includes a backend (Express), frontend (React), and worker processes. A monorepo structure simplifies dependency management and coordination between packages.

## Decision
Use a single repository with separate directories for backend, frontend, and Docker configuration. Root `package.json` coordinates workspace scripts.

## Consequences
+ Single source of truth — backend and frontend versions stay in sync
+ Shared Docker Compose for all services
+ Simplified CI/CD — one repo to build and deploy
- No TypeScript project references between backend and frontend (separate TS configs)
- Root `npm install` must install dependencies in both backend and frontend
- No shared types package — manually duplicated or defined independently

## Evidence
- `backend/package.json` + `frontend/package.json`: Separate dependencies
- `docker/docker-compose.yml`: Both services defined
- Root `package.json`: Workspace scripts
