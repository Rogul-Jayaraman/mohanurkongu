# ADR-012: Docker Compose for Dev and Production Deployment

**Status:** ACCEPTED

## Context
The platform runs multiple services (PostgreSQL, Redis, Backend, Frontend, Workers, Nginx). A consistent deployment approach is needed for development and production.

## Decision
Use Docker Compose with two configurations:
- `docker-compose.yml`: Development (HMR, hot reload, dev ports exposed)
- `docker-compose.prod.yml`: Production (multi-stage builds, PM2, optimized)

## Consequences
+ Consistent environment across dev and prod
+ All dependencies containerized — no manual postgres/redis setup
+ Nginx as reverse proxy for both SPA and API
+ Single command to start the full stack
- No health checks configured (containers not waiting for dependencies)
- No CI/CD pipeline — manual deployment
- PostgreSQL port exposed to host network in dev config
- No SSL termination in compose (expected to be handled externally)

## Evidence
- `docker/docker-compose.yml`: 6 services (postgres, redis, backend, frontend, workers, nginx)
- `docker/docker-compose.prod.yml`: Production variant
- `docker/nginx/templates/`: Nginx config templates
